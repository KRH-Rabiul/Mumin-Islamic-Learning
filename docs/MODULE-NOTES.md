# Mumin Module 7 — Daily Life

This module is an informative guide to everyday life based only on Quranic verses and cited hadith sources.

## Content policy
- No generic motivational advice is presented as Islamic guidance.
- Explanations are short paraphrases of the cited source material.
- Each major rule includes a Quran or hadith reference.
- Where a matter can involve detailed fiqh disagreement, the module avoids presenting an uncited universal ruling.

## Main sections
Foundation, Parents & Family, Speech, Family & Relationships, Food & Drink, Privacy & Permission, Neighbors & Society, Work/Earning/Wealth, Character, Prohibitions, What to do after mistakes, FAQ.

# Mumin Module 6 — Hadith Gateway

## What changed
Module 6 was intentionally simplified. The previous in-page API/CDN database reader has been removed from the runtime.

Mumin now acts as a clean **Hadith Gateway**:
- beautiful local Mumin UI
- searchable list of six major collections
- direct links to HadithBD collection pages
- no API key
- no chapter-by-chapter JavaScript data loading
- no third-party JSON dataset stored in the page
- no fabricated or locally rewritten large hadith collection

## Primary external source
HadithBD: https://www.hadithbd.com/hadith/

HadithBD currently provides a large Bengali hadith library with book, chapter, hadith number, Arabic, Bengali translation and grading/reference information on its pages. The Mumin page does not claim ownership of or reproduce the full external database.

## Book links used
- Sahih al-Bukhari: https://www.hadithbd.com/hadith/bukhari/
- Sahih Muslim: https://www.hadithbd.com/hadith/muslim/
- Sunan Abi Dawud: https://www.hadithbd.com/hadith/abu-dawud/
- Jami at-Tirmidhi: https://www.hadithbd.com/hadith/tirmidhi/
- Sunan an-Nasa'i: https://www.hadithbd.com/hadith/nasai/
- Sunan Ibn Majah: https://www.hadithbd.com/hadith/ibn-majah/

## Files
- `hadith.html` — new gateway page
- `hadith.css` — dedicated UI styling
- `hadith.js` — local search, theme, mobile menu and reveal animations only

## Why this architecture
A hadith module should prioritize clear source attribution and maintainability. Keeping a huge copied dataset inside Mumin would create unnecessary synchronization and data-quality problems. The gateway model keeps the Mumin experience simple while sending the reader to a dedicated source for the full text.

# Mumin Module 5 — Ramadan

A standalone Ramadan learning hub integrated into the Mumin Islamic Learning Website.

## Included
- Ramadan hero and navigation
- Ramadan foundation and Quran references
- Fasting guide with tabs: basics, adab, exemptions
- Sehri and Iftar guidance
- Taraweeh / night prayer section
- Ramadan guidance and worship sections; a full 30-day Juz progress tracker is not part of the current shipped build
- Daily Ramadan worship checklist with local progress storage
- Laylatul Qadr guide
- Last 10 nights planner
- Authenticity-aware Laylatul Qadr dua with copy/save actions
- FAQ section
- Responsive/mobile layout
- Shared Mumin typography and navigation

## Main files
- `ramadan.html`
- `ramadan.css`
- `ramadan.js`

## Primary source references used in the page
- Qur'an 2:183 — purpose of fasting / taqwa
- Qur'an 2:185 — Ramadan and revelation of the Qur'an
- Sahih al-Bukhari 1904 — fasting as a shield and restraint from quarrelling
- Sahih al-Bukhari 1923 — blessing of suhur
- Sahih al-Bukhari 1957 — hastening iftar
- Sahih al-Bukhari 2008–2009 — night prayer in Ramadan
- Sahih al-Bukhari 2017, 2020–2021 — seeking Laylatul Qadr in the last ten nights / odd nights
- Jami` at-Tirmidhi 3513 — dua for Laylatul Qadr

The module intentionally avoids presenting a single personal fiqh ruling for circumstances where scholars differ. For individual rulings, users are directed to qualified scholars.

# Quran Module Fixes

- Ayah loading no longer depends on Bengali-pronunciation availability. Arabic text and Bengali meaning are validated by ayah count and can be cached locally in IndexedDB.
- Surah request tokens prevent an older asynchronous response from overwriting a newly selected Surah.
- Bengali meaning uses the `translation` field, never the Arabic `text` field.
- Pronunciation is never generated by the app. A missing pronunciation is fail-safe rather than guessed.
- Surah Introduction is data-driven and contains only factual, source-attributed fields: revelation period, context, core themes, and reported occasion of revelation where appropriate.
- Specific virtues remain in the separate Fazilat tab. Unsupported special virtues are not invented.
- Internal implementation details are removed from the user-facing Introduction, Ayahs, Fazilat, and Reference sections.
- No backend, PHP, Node server, Spring Boot, MySQL, or XAMPP dependency is introduced.
